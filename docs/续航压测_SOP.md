
> 目标：在最短时间内测出 BK7258 DevKit（velapet）的**真实整机续航**。
> 结论先行：**用"满电→带重载→跑到自动关机"的整机放电法**，直接得续航小时数，绕开串表/供电的所有坑。
> 适用场景：临近截止、要快出可信数字。

---

## 一、为什么用整机放电法（先看这段，少走弯路）

之前试过"万用表串电池线量电流"的估算法，踩了两个坑，最终放弃：

1. **串表 + 插 USB = 测的是充电电流，不是耗电。**
   两个 Type-C 口都带 5V(VBUS)，插上就给板子供电 + 给电池充电。表串在电池线上量到的是**充进电池的电流**：
   空闲时读 37mA、跑 `lcdtest oeye`（更耗电）反而降到 24mA——"负载越大电池电流越小"正是充电的铁证，红灯=充电灯。

2. **能敲命令的 NSH 只在板载 CH340（Type-C）上，拔了 Type-C 就没法敲命令。**
   - NSH 控制台 = **UART0 = 板载 CH340**，在系统里是 **`/dev/ttyUSB*`**（ch341 驱动，115200 8N1）。
   - 外接的 CH343 USB-UART 适配器是 **`/dev/ttyACM*`**（cdc_acm 驱动）。
   - 飞线焊的"大核 log 口 / DBG UART / GPIO6-7"**不是交互 NSH**——能打开串口、但没输出、打不进字。
   - 死结：**要敲命令 → 必须插带 CH340 的 Type-C → 必然供电充电 → 电池不放电 → 测不了续航。**

> 所以放弃串表估算，改用**整机放电法**：不量电流，直接计时"满电跑到关机要多久"。

## 二、SOP（照着做）

### 1. 还原 + 充满
- 把万用表从电池串联里撤掉，**电池线恢复原样直连**，确认板子能正常开机。
- 插充电，**充到绿灯（满电）**。

### 2. 起负载：用 `camera velapet`（已实测：拔线能继续跑）
满电后插上出 `ttyUSB0` 的那个 Type-C，`picocom -b 115200 /dev/ttyUSB0` 进 nsh，敲：
- **`camera velapet`** —— 摄像头 + 双屏 + LED 一起跑，重载、掉电快、是**最坏情况续航**（报告最有说服力）。
  **实测拔掉 Type-C 后它能继续在电池上跑**（没人脸/手势时只有"睁眼+眨眼"两种动作，会周期眨眼 = loop 仍活着，属正常）。

> ⚠️ **不要用 `lcdtest oeye` 做放电负载**：实测拔掉 Type-C 后它跑几秒就**卡死**（前台命令，控制台一断就挂）。仅 velapet 能拔线续跑。
>
> ⚠️ 别用空闲测：1000mAh × 空闲 ~13mA ≈ 70+ 小时，3 天跑不完。**压测就要带重载**，快且是保守值。

### 3. 关键一步：拔 Type-C，看能不能继续跑
起好 `camera velapet` 后**拔掉 Type-C**，盯 10 秒：
- **画面继续跑（周期眨眼、不重启）** → 无缝切电池，成了。**记下此刻时间 = T0（起跑）。**（已实测 velapet 走到这步 OK）
- **一拔就黑屏/重启** → 命令丢了，走「四、兜底」。

### 4. 跑到关机，记时间
让它一直跑到**自动关机（屏灭）**。快没电时（**< 3500mV**）**红灯会闪**，是结束预警。
- **续航 = 关机时刻 − 起跑时刻**。
- 用手机拍屏幕 + 一个钟表，或每 15~30 分钟回来看一眼，别错过关机点。

### 5. 记录进报告
写清"**XX 负载场景下满电续航 = N 小时 M 分**"，注明负载（`camera velapet` / `lcdtest oeye`）与电池容量（1000mAh）。

## 四、兜底：如果第 3 步"一拔就重启"

拔 Type-C 会重启 → 没法靠拔线保持负载。最稳的办法是**让板子开机自动带载跑**：
在开机启动脚本 `rcS` 里加一行（如 `lcdtest oeye &`），重烧一次。之后**拔掉所有 USB、纯电池上电也会自动带载放电**，只管计时到关机。

- 改动极小、风险很低（不碰控制台 UART 配置）。
- 需要重编 + 用 Type-C 重烧一次固件。
- 如需，找 Kiro 帮忙加这一行并重烧。

## 五、电量读数说明（重要，别被误导）

`lcdtest bat` 的电量是**纯电压换算**（raw ADC → mV → %），**没有库仑计**，所以：
- **带载时 % 会掉、拔载/重启会回弹**，这是**负载压降（voltage sag）**，不是真掉电。
  实测：满电静态 `4200mV/100%`；`camera init` 后摄像头持续供电 → `4123mV/91%`；重启关掉摄像头 → 回 `4202mV/100%`。
- **进度别看 %**：续航只认"**跑到自动关机的时间**"（关机=真·欠压保护 <3500mV）。
- 要记曲线就记 **mV**（比 % 靠谱），且注意是带载压降后的值。
- `camera`（无参数）会**重启板子**，测续航时别乱敲；velapet 起来后就别再碰键盘，直接拔 Type-C 计时。

> **两种口径**：
> - 快法（串表）：`续航 ≈ 1000mAh ÷ 满载电流(mA)` = 7h15m（上限）。**推荐写报告用这个**，2 分钟出。

>

### 续航总结（串表法实测，1000mAh）

| 场景 | 说明 | 实测电流 | 续航估算(1000÷I) |
|---|---|---|---|
| **真待机（复位进 NSH、不跑命令）** | 熄屏、无摄像头/DVP | **~16 mA** | **≈ 62 h（约 2.6 天）** |
| 重载 `camera velapet`（**运行中·续航依据**） | 摄像头+双屏+LED | **~135 mA** | **≈ 7.4 h（7h25m）** |
| `lcdtest oeye`（运行中） | 双屏眼神动画 | ~80 mA | ≈ 12.5 h |
| **`camera hr` 退出后** | 摄像头/PSRAM/DVP 全下电 | **16 mA ✅**（110→16，= 真待机） | ≈ 62 h |
| **kws enroll+run 后** | 音频 `audio_deinit` 全下电 | **16 mA ✅**（32→16，= 真待机） | ≈ 62 h |
| **真待机 / `camera hr` / `kws` 退出** | 全下电（未用 LCD，或刚复位） | **15~16 mA ✅** | ≈ 62 h |
| **跑过 LCD 命令后退出**（`lcdtest oeye` / `camera velapet`，未复位） | 见下 | **~33 mA** | — |

> **LCD 命令退出后 ~33mA 残留 —— 实测规律与诚实结论（先前两次定位均已证伪）**：
> - **实测规律**：**复位后**第一条 `camera velapet` 退出 = **15mA**；但**跑过任一 LCD 命令后**（`lcdtest oeye`，或再次跑 velapet），退出空闲**稳定停在 ~33mA，且只有硬件复位能清除**（reset→velapet=15；oeye→velapet=33）。
> - **已排除**：pwrdump 实测确认残留(33mA)时 `PSRAM_CKEN=0、SPI1_CKEN=0、AUD_CKEN=0、CAM_CLK=0、PWD_AHBP=1(AHB 域已关)、pwdaudpll=1、LCD GPIO 全拉低` —— **15mA 态与 33mA 态这些寄存器完全相同**。故残留**既非 LCD 面板/背光硬件（先前"硬件供电路径"判断证伪）、也非 AHB 域（"AHB 未关"判断亦证伪，Claude 显式关 AHB 后电流不变）**。
> - **诚实结论**：这 ~18mA 是 **LCD 使用触发的某个时钟树/子系统状态**，**不在当前 pwrdump 覆盖的寄存器内**、仅硬件复位可清。未完全定位，需**全时钟树/PLL 寄存器 dump 或 SWD** 深挖，列为后续。
> - **不影响续航口径**：续航以运行态电流计（velapet ~135mA→7.4h）；演示 velapet 为运行态展示，跑完复位即回 16mA。

> **v2 优化：PSRAM 彻底下电（大头 ~90mA），实测生效。**
> 根因：`bk7258_psram_init()` 永久开启 PSRAM LDO + AHB 电源域 + 外设时钟，从不关闭。新增 `bk7258_psram_deinit()` 严格逆序关闭（关时钟 bit19 → 关 LDO enpsram → 关 AHB PWD_AHBP → 清 g_psram_init_done），velapet/hr/track/preview 退出路径均已调用。
> **实测（UT181A 串表法）**：`camera hr` 退出 **110→15mA**，回真待机；命令可重新运行（PSRAM re-init 正常）、kws/mic 功能不受影响 → **AHB 域下电安全**。
> **v3：退出关 LED**（oeye/blink/velapet 退出把 P40/P41 拉低）。
> **v4（音频 + LCD SPI1 完整下电）**：
> - `lcd_spi_deinit()` 修复：**无条件清除 SPI1_CKEN bit9**（不再从 `g_saved_sys_clk_en` 恢复），velapet/oeye 退出后 LCD 时钟归零。
> - `audio_dac_deinit()` 增强：播放结束后完整逆序 `audio_init()` —— 关 CKSEL_AUD → 关 APLL（`ana_setbit(ANA_REG5,13,1)`）→ 关 SYS_AUD_CKEN(bit30) → 关 PWD_AUDP(bit6)。`audio_beep`/`audio_play_melody`/`bk7258_play_pcm16k` 均在播放后调用 `audio_dac_deinit()`，**放完即关音频**。
> - 所有命令退出后传感器/framebuf 已关闭，再次使用需手动 `camera init` + `camera buf`（入口有清晰错误提示）。
> - `camera pwrdump` 可 dump 寄存器复查。

### 关机/深睡电流怎么测（说明）
本板是开发板，**没有真正的软关机/PMIC 下电**，"关机"只有两种可理解的口径：
- **欠压保护关机**：电池放到 ~3.0–3.3V 触发保护，此时基本断电，电池线电流≈0（只剩极小漏电）。
- **深睡电流（需实现 PM 后才有意义）**：当前固件无深睡。若将来做了 WFI/停机深睡，测法同串表——进深睡态后读电池线电流（可能到 µA/mA 级，需用 UT181A 的 mA/µA 档提高分辨率）。
> 现阶段"关机电流"无独立可测态；要给"最低功耗"数，就是上表的**真待机 ~16mA**。

## 七、注意事项

- 一次深放电（跑到欠压保护关机）对锂电无碍；但**别反复深放**，测完及时充回。
- 关机是电池欠压保护动作（约 3.0~3.3V 截止），属正常，不是板子坏了。
- 报告里注明这是**特定重载场景**续航，不是待机续航；两者差异很大，勿混。
