## 2. 摘要

VelaPet 是基于 **openvela(NuttX)**、运行于 **BK7258 DevKit** 的桌面 AI 情感陪伴机器人,主打**完全离线、数据不出设备**。项目从零完成 BK7258 的 **openvela 首次板级移植**与整套外设驱动,并落地三项实机能力:①**摄像头指尖 rPPG 测心率**(实测 64.6 bpm、good);②**纯 C 自研 MFCC+DTW 离线命令词识别与语音应答**(支持唤醒词"你好 openvela");③**双圆屏拟人眼神 + 体感交互**。作品覆盖 openvela **图形/AI/多媒体**三类能力,全程 AI 辅助并沉淀 2 个可复用 Skill。创新点是把行业 AI 玩具"联网才智能、隐私上云"的短板反做成"**端侧离线 + 健康关怀 + 新板生态**"的卖点。

## 3. 正文

### 3.1 绪论

**项目背景与问题定义**
市面桌面 AI 陪伴玩具(机器狗、宠物机等)普遍存在三个痛点:(1) **强依赖联网**——语音/对话链路走云端,断网或弱网即"失智"、转圈等待;(2) **隐私上云**——麦克风/摄像头数据上传第三方服务器;(3) **健康能力缺位或依赖专用传感器**堆料。面向儿童陪伴、老人关怀、桌面互动等场景,用户其实更需要"断网也能用、数据留在本地、还能顺手关心健康"的产品。

**技术难点**
1. **全新硬件平台从零适配**:BK7258 在 openvela 此前无任何适配,且其 Datasheet 仅到功能级、无寄存器映射,寄存器细节只能从 ARMino SDK 源码反推;需完成启动、控制台到全套外设 BSP。
2. **无 PPG 传感器却要测心率**:只能用摄像头做 rPPG,需在 MCU 上完成采样、滤波、频域/自相关估计与置信度判定。
3. **离线语音且合规**:不能用闭源识别 blob(License 风险),又要在 MCU 上离线跑通"唤醒 + 命令词 + 拒识 + 语音应答"。
4. **资源紧张**:内部 SRAM 仅 336 KB,静态占用高,须把大缓冲搬到 PSRAM、把特征压缩,才能让端侧算法与 shell 稳定共存。

**创新点**
- **技术**:纯 C、零第三方运行时的自研 **MFCC+DTW** 离线命令词引擎(含自写 radix-2 FFT / Mel 滤波 / DCT / DTW / CMVN),Apache-2.0 干净可交付;摄像头 **rPPG 三窗中位数交叉验证**,在无传感器条件下算出心率并给出 good/fair 置信度。
- **场景**:把"离线健康关怀"引入桌面陪伴玩具,断网可用、数据不出设备。
- **交互**:双圆屏"眼神" + 加速度计体感 + 声光 LED,组成拟人情感闭环;语音唤醒即应答。

  | 隐私 | 音视频上云 | 数据不出设备 |

### 3.3 核心算法与技术原理

**(A) 离线命令词识别:自研 MFCC + DTW(端侧,纯 C,零第三方运行时)**

- **前端 MFCC**(`app/kws/kws_mfcc.c`,全自写):16 kHz 单声道 PCM → 预加重(0.97)→ 25 ms 帧 / 10 ms 帧移 + Hamming 窗 → **自写 radix-2 FFT(512 点)** → 功率谱 → **26 通道 Mel 滤波器组**(300–8000 Hz)→ 取对数 → **DCT-II** → 13 维倒谱;再做**能量端点检测(VAD)** + **逐句 CMVN**(均值方差归一,抗增益/信道漂移)。
- **时间归一**:每句语音的有效段线性重采样到**定长 48 帧**,消除语速/时长差异,让 DTW 比"发音内容"而非"时长"(这是早期变长方案的主要误判来源;同时显著降低 RAM)。
- **匹配 DTW**(`app/kws/kws_dtw.c`):查询序列与模板做动态时间规整,取**路径长度归一的最小距离**。模板以 **int16 量化**(scale=64)存储省 BSS,最多 6 槽。
- **判定策略**(`app/kws/kws_main.c`):接受当且仅当 `best_dist ≤ 阈值(11.0)` **且** `best_dist ≤ 0.88 × 最近异词距离`(异词裕度,防"都有点像");并设**静音门**(采样峰值 `peak < 300` 判无语音),防单唤醒词场景被环境噪声误触发。
- **唤醒 + 离线语音应答**(`kws wake`):命中唤醒词"你好 openvela"→ 播放预置离线 PCM"你好,我在";没听清/不确信 → 播放"没听清,请再说一遍";无问候数据时退化为提示音。
- **采集原语**(`bk7258_mic_record_16k`):16 kHz 单声道轮询采集,采集窗口 1.5 s(为反应时间留裕度,末字不被截),VAD 会把多余静音裁掉;并打印 `level: peak/rms` 便于现场自查收音质量。

**(B) 摄像头指尖测心率:rPPG(端侧)**

- 手指轻盖 GC2145 镜头,采集约 **450 帧**(实测 ~27.7 fps,约 16 s);提取皮肤透光的绿/亮度通道随心搏的微小变化。
- 做去趋势/带通滤波后,分**3 个时间窗**分别用**自相关**估计心率,并计算相关强度 `corr` 与灌注指数 `PI`。
- **三窗交叉验证 + 中位数**:对有效窗的心率取**中位数**(而非平均,以甩掉离群窗);置信度判定——**当三窗 spread ≤ 4.0 bpm 且 corr ≥ 50% 且 PI ≥ 0.8% 判 good,否则 fair**;有效窗不足则提示"重测"。这套自一致性检查是无参照下保证可信度的关键。

**(C) openvela 系统能力的深度运用**
- **图形**:基于 **LVGL** 在**双 GC9D01 圆屏**上渲染拟人眼神(NEUTRAL / HALF / SMOOTH BLINK / HAPPY),含局部刷新的瞳孔/眨眼动画。
- **多媒体**:DVP 摄像头采集(帧缓冲驻留 16 MB PSRAM)+ 音频采集/播放(麦克风 PCM、喇叭 PCM 应答)。
- **系统/内核**:NuttX 任务与 NSH 控制台、KMM 堆、PSRAM 内存窗口、GPIO/I²C/ADC 等子系统。
- **对 openvela 的拓展与改进建议**:本作品为 BK7258 贡献了首套可复用 BSP;建议上游补充 BK7258 chip/board 支持与 PSRAM 堆化范例,并完善"analog 串行总线寄存器"与"SYS 中断聚合器"的移植文档(见随仓 Skill)。

### 3.4 系统实现

**软件 / 固件架构**
```
NSH 应用 (apps/examples/*)  ── camera / kws / mic / lcdtest
        │  (软链自 contest 仓 app/*)
        ▼
板级 BSP (boards/contest2026_098_board → contest 仓 board/contest_board)
   src/: gc9d01(双屏) · camera(GC2145) · audio(单麦 MIC1+喇叭) · accel(SC7A20H)
         battery(ADC) · gpio/led · appinit
        │
        ▼
openvela / NuttX 内核 + arch/arm/src/bk7258(chip 层:启动/PSRAM/时钟/中断)
```
仓库通过 manifest(`contest2026_098_zhanshangxingguang.xml`)的 `<linkfile>` 把 `board/` 与各 `app/` 软链到 openvela 编译树对应位置。

**数据流与关键流程(以 `kws wake` 为例)**
```
麦克风PCM(16k,1.5s) → 静音门(peak<300?) → VAD端点检测 → 定长48帧重采样
   → MFCC(FFT/Mel/DCT/CMVN) → 与各模板 DTW → 取最近 & 异词裕度判定
   → 命中? ─是→ 播放"你好,我在"(离线PCM)
           └否→ 播放"没听清,请再说一遍"
```
`camera hr` 流程:`camera init`→`camera buf`(PSRAM 帧缓冲)→`camera hr`(采 450 帧 → 三窗自相关 → 中位数 + 置信度)。

**硬件设计与适配(新硬件适配赛道核心得分项)**
- **是否完成全新硬件平台适配 / 驱动开发:是。**
- **芯片 / 开发板**:Beken **BK7258** DevKit(双核 Armv8-M STAR-MC1,FPU;板载 CH340 UART,Flash XIP,内部 SRAM 336 KB,外部 **PSRAM 16 MB**——`psram id` 实测 `chip ID=0x8d08 / size=16384 KB (16 MB)`,APS128XXO)。
- **外接/板载模块与驱动类型**:
  | 模块 | 型号 | 接口 | 驱动 |
  |---|---|---|---|
  | 双圆屏 | GC9D01 ×2 | QSPI | 自写显示驱动 + LVGL 接入 |
  | 摄像头 | GC2145 | DVP + SCCB | 自写采集/YUV 解析 |
  | 音频 | 单麦 MIC1 + 喇叭 | I²S/模拟 | 自写 ADC/DAC 采播原语 |
  | 加速度计 | SC7A20H | I²C | 自写手势(拿起/摇动) |

**应用 / 交互端设计**
纯设备端交互(无手机 App/网关):双圆屏眼神为主视觉反馈;加速度计"拿起→睁眼、摇动→开心",LED 红/绿表情灯,低电红灯闪;语音唤醒即用喇叭应答。

**可靠性与稳定性(量化)**

**(1) 命令词识别 —— 判定裕度量化(基于上表真机日志)**

判定规则:接受 ⇔ `best_dist ≤ 阈值 11.0` **且** `best_dist ≤ 0.88 × 最近异词距离`。据此对实测样本量化如下:

| 场景 | best_dist | 最近异词 | 判定线(0.88×异词) | 结果 | 裕度 |
|---|---|---|---|---|---|
| 命中"开始运动" | 3.84 | 12.52 | 11.02 | MATCH | 距判定线余量 **65%**(3.84 远低于 11.02) |
| 命中"查心率"(另测) | ~12.5 类 | — | — | 见下说明 | 需与本人 enroll 一致 |
| 拒识(无关语音) | 11.49 | 13.73 | — | REJECTED | best 高于阈值 11.0,**安全拒识、不误报** |

> 说明:命中裕度 = (判定线 − best_dist)/判定线;拒识时 best_dist(11.49)> 绝对阈值(11.0),不满足接受条件即拒识。近场削波会缩小裕度(见 3.7),实测"嘴离麦 8–12 cm + `level:peak` 落在 2000–15000"可稳定复现高裕度命中。

**(2) 命令词命中率 / 漏报率实测(共 67 次正样本)**

测试条件:本人 enroll;**登记与识别保持同一距离(嘴离麦约 10~15 cm)、手扶下颚稳定发声**;每次仅 enroll 单个命令词(故仅绝对阈值 11.0 参与判定,日志中 `other=0`)。原始串口日志见仓内 `docs/yundong.txt`、`docs/chaxinlv.txt`。

| 命令词 | 正样本次数 | 命中 | 漏报 | 命中率 | 命中距离 min/均/max |
|---|---|---|---|---|---|
| yundong(开始运动) | 35 | 33 | 2 | **94.3%** | 7.55 / 8.73 / 10.89 |
| chaxinlv(查心率) | 32 | 30 | 2 | **93.8%** | 6.61 / 8.92 / 10.89 |
| **合计** | **67** | **63** | **4** | **94.0%** | — |

- **命中率(识别准确率)= 94.0%**、**漏报率(FN)= 6.0%**、**错词误识 = 0**(63 次命中全为正确词)。
- 4 次漏报的 DTW 距离为 11.06~11.75,**均刚越过阈值 11.0**,属临界漏识而非误识,符合"宁拒不误报"的安全取向。
- **距离一致性是关键**:实测保持"登记/识别同距 10~15 cm + 手扶下颚"时命中率稳定在 94%;距离或音量大幅漂移会因近场削波拉低命中(见 3.7)。

**(2b) 误报率(FP)实测 —— 对未登记的无关语音**

说**非命令词**内容,考察是否被误判为 MATCH(peak>300 才计为有效样本)。分两种登记规模对比:

| 登记规模 | 无关语音 | 有效样本 | 误报(误 MATCH) | **误报率 FP** | 机理 |
|---|---|---|---|---|---|
| 单命令词(仅 yundong,`other=0`) | "我要吃饭"等 | 4 | 3 | **≈75%** | 异词裕度失效,仅绝对阈值 11.0 兜底 |
| **双命令词(yundong+chaxinlv)** | "你好 openvela"(未登记) | 27 | 3 | **11.1%** | 异词裕度生效,拒识能力大幅提升 |

- **关键发现**:登记词从 1 个增到 2 个,FP 从 ≈75% 降至 **11.1%**——说明本引擎的拒识主要依赖"异词裕度(相对比较)"而非绝对阈值,**多命令词部署为推荐用法**。原始日志见仓内 `docs/REJECTED.txt`(双词 OOV 抽样)。
- 双词模式 27 次有效样本中 **24 次正确拒识**,3 次误判为 chaxinlv(dist 9.76~10.02,other 11.48~11.73);另有 9 次 peak<300 被**静音门**挡下(判"太安静"、不计),静音门有效防止空录误触发。

**(3) 测心率 —— 自一致性与漏检兜底(量化)**

- **三窗一致性**:实测 win0/1/2 = 62.0/60.0/60.1 bpm → **极差 spread = 2.0 bpm ≤ 4.0**(good 门限);另一组 corr=73%、PI=3.8% 同判 good。
- **置信门限**:仅当 **三窗 spread ≤ 4.0 bpm 且 corr ≥ 50% 且 PI ≥ 0.8%** 判 good,否则判 fair 或提示"重测"——**spread 过大/有效窗不足时不硬报数**,避免给出不可信心率(健康类作品安全底线)。

**(4) 异常恢复与长稳**

- `camera hr` 在连续无帧(如从 LCD 场景切入未重新 init DVP)时 **早退报错 `-ETIMEDOUT`** 而非假死。
- 长时间运行 `free` 无碎片/泄漏病征;内部 SRAM 静态占用约 93%,堆余 13–20 KB,shell 与端侧算法稳定共存。

### 3.7 总结与展望

**成果总结**
- 完成 BK7258 的 **openvela 首次板级移植**与整套外设 BSP(双屏/摄像头/音频/加速度计/电量/LED/PSRAM)。
- 在端侧落地三项实机能力:**摄像头 rPPG 测心率、纯自研离线命令词识别与语音应答、双屏拟人眼神 + 体感交互**,并同时覆盖 openvela 图形/AI/多媒体三类能力。
- 全程 AI 辅助开发,沉淀 2 个可复用 Skill,回馈 openvela 社区;全部代码 Apache-2.0 原创、命令词引擎零第三方运行时。

**应用前景与商业价值**
- **目标受众**:有陪伴/健康关怀需求的家庭——儿童桌面伙伴、独居老人关怀、注重隐私的用户;地域不限,尤适网络不稳或注重数据本地化的场景。
- **商业模式**:硬件本体 + 可选的"离线技能包/表情包"增值;面向教育、适老、文创 IP 联名等方向规模化。
- **规模化潜力**:方案以低成本 MCU(BK7258)+ 摄像头/双屏实现"离线健康 + 拟人交互",BOM 可控;端侧离线天然规避云端算力成本与合规风险。

**不足与未来工作(诚实说明)**
- **测心率**:主打指尖 rPPG(稳定);**隔空 rPPG** 因人脸区信噪比低、准确率有限,列为探索方向。
- **离线命令词**:**说话人相关**(需本人登记)、词表规模小;对**近场收音敏感**(板载麦无 AGC,贴麦会削波),建议嘴离麦 8–12 cm;语音应答为**预置离线问候**,非自由对话。**拒识依赖"异词裕度"**:单命令词部署时误报率偏高(实测 ≈75%),登记 2 个词后即降至 11.1%(见 3.5),故**推荐至少登记 2 个以上命令词**;亦可按需调低阈值/加大词间裕度换取更低误报。后续可升级 **TFLM + DS-CNN(int8)** 做说话人无关识别、加软件 AGC/归一,自由对话可选联网走云端 LLM(如 MiMo)。
- **体感**:轻拍(click)在本板不稳,已改用**拿起/摇动**;`emo` 表情存在左右眼镜像待修。
- **视觉识别 / 人脸跟随**:属探索/进阶,未达稳定演示标准,暂不计入核心功能。
- **NFC(MFRC522)**:未实现,不在本次范围。
- **音频/麦克风**:采用**单路 MIC1、16 kHz**;MIC2 为芯片硬件 AEC 回采能力,**AEC 降噪 / 双麦降噪 / 声源定位未实现或未验证**(早期声源定位实验代码已取消)。
