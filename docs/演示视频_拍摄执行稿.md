# VelaPet 演示视频 · 拍摄执行稿(目标 4:30,≤5min)

形式:**串口屏幕录制 + 板子实拍**,后期剪在一起(画中画/切镜)。口播为**逐字中文稿**,直接照读。

---

## 一、开拍前 5 分钟自检清单

**环境 / 设备**
- [ ] 安静房间(命令词要现场说话);**光线稳定充足**(测心率靠环境光,别让光线忽明忽暗)。
- [ ] 板子固定放稳;串口连好:`fuser -k /dev/ttyUSB0; picocom -b 115200 /dev/ttyUSB0`。
- [ ] **终端字号调大**(方便视频看清);窗口拉宽,避免自动换行打乱输出。
- [ ] 固件是最新 `dev-ai` 编译烧录(含 `camera hr` / `kws` / `lcdtest`)。
- [ ] 手机/录屏软件就位;本稿口播词另开一屏或打印。
- [ ] **wifi/热点全程关着**(用来佐证"离线")。

**逐条复测(录之前先跑一遍确认稳)**
- [ ] `camera init` → `camera buf` → `camera hr`:手指轻盖摄像头、**保持静止**,末行出 `... good` 且 bpm 合理(≈55–90)。若出 `fair`/乱跳:调光、手指盖严一点、别压太紧,重试 2–3 次找到稳定手感。
- [ ] **预先登记(录制时直接 run,省时间)**,含**大赛指定唤醒词**:
      `kws clear`
      → `kws enroll nihaoopenvela`(说"你好openvela",**念快一点**,避免超过 1 秒被截)×2
      → `kws enroll chaxinlv`(说"查心率")×2
      → `kws enroll yundong`(说"开始运动")×2
      → `kws list`(应显示 6 条)。
      验证:说"你好openvela"→ `MATCH nihaoopenvela`;说命令词/无关话分别命中/拒识。
      > 唤醒词较长、1 秒窗口可能截尾,但登记与识别截同一段,匹配不受影响(念法保持一致即可)。
- [ ] `kws run` 说"开始运动"→ `MATCH yundong`;说一句无关话 → `REJECTED`。各试 2 次确认稳。
- [ ] `lcdtest oeye`、`lcdtest blink`:双屏眼神/眨眼正常。
- [ ] **情感整合**用 `camera velapet`(已确认真驱动眼睛 + LED):初始困倦眼 → **拿起→睁眼 + 绿灯** → **摇动→开心 + 红绿双灯** → 低电时**红灯闪("饿了")**。拿起/摇动由加速度计驱动、不依赖摄像头,可靠。
      > 唯一注意:有人脸时 TRACK 态眼睛可能轻微抖动——拍摄时**让板子别正对人脸,只演拿起/摇动**即可。若仍想更稳,退回 `lcdtest oeye`(眼神)+ `lcdtest accel g`(手势串口打印)分开拍。
- [ ] `lcdtest bat`:读出电量数值。低电红灯闪烁**需电量真的低**——若现场造不出,**口播带过即可,不强拍**。
- [ ] `lcdtest led <pin> <0|1>`:确认你板子的 LED 引脚号(红灯常见 P40),点亮/熄灭各一次。

> 只要"测心率出 good、命令词说对能中说错能拒、眼神能亮"这三样稳,就可以开拍。其余(低电红灯/LED)拍到算加分,拍不到不卡。

- **画面**:实拍板子全貌,双圆屏亮着眼神;叠标题字幕 "VelaPet · 跑在 BK7258 上的 openvela 端侧 AI 情感陪伴机器人"。

### 幕 1 · 适配成果(证明"底座硬")—— 40s(0:25–1:05)
- **画面**:屏幕录制串口;穿插实拍双屏点亮。
- **命令**(依次敲):
  ```
  nsh> help
  nsh> free
  nsh> lcdtest oeye
  ```
- **口播**:
  > "先看底座。`help` 列出我们移植的能力——摄像头、离线命令词、双屏、麦克风都在。这块板从启动引导、UART 控制台,到双 QSPI 圆屏、DVP 摄像头、音频、加速度计、电量 ADC、16 兆 PSRAM 的板级驱动,都是我们从零适配的,代码已经开源合入大赛专属仓。`lcdtest oeye` 点亮双圆屏——这就是它会传情的两只眼睛。"

### 幕 2 · 亮点一 · 摄像头指尖测心率(rPPG)—— 60s(1:05–2:05)
- **画面**:画中画——实拍手指轻盖摄像头,同屏串口输出;`sampling` 那 ~16 秒可 2–3 倍速。
- **命令**:
  ```
  nsh> camera init
  nsh> camera buf
  nsh> camera hr
  ```
- **口播**(敲下 `camera hr` 后,趁采样这段讲):
  > "第一个亮点:这块板**没有心率传感器**,但我们用摄像头把心率算出来了。手指轻轻盖住镜头保持不动,摄像头在采集皮肤下血液流动引起的微小颜色变化,这就是 rPPG。它正在采 450 帧、大约十几秒,做带通滤波和自相关,分三个窗口交叉验证。"
  > (出结果后)"看,HR 60 bpm,三个窗口一致、判定 good——**没有传感器,硬是用一颗摄像头量出了心率**,难点和创新都在这里。"

### 幕 3 · 亮点二 · 离线命令词识别(自研 MFCC+DTW)—— 75s(2:05–3:20)
- **画面**:屏幕录制串口 + 实拍你对着板子说话;可给"wifi 已关闭"一个特写。
- **命令**(已预先登记好,这里直接演):
  ```
  nsh> kws list                 # 你好openvela / 查心率 / 开始运动
  nsh> kws run     ← 说“你好openvela”(大赛指定唤醒词)
  nsh> kws run     ← 说“开始运动”
  nsh> kws run     ← 说一句无关的话(如“今天天气不错”)
  ```
- **口播**:
  > "第二个亮点:离线命令词识别,**纯自研的 MFCC 加 DTW**,一行第三方库都没用,完全开源合规。我提前登记了大赛统一指定的唤醒词'你好 openvela',还有'查心率''开始运动'。注意——**现在板子是断网的**。"
  > (`kws run`,清晰说"你好 openvela")"'你好 openvela'——命中,这是大赛指定的统一唤醒词。"
  > (`kws run`,说"开始运动")"'开始运动'——命中,距离很小,和别的词拉开一大截。"
  > (`kws run`,说无关话)"再说句无关的——直接拒识,不误报。麦克风采 PCM、算 MFCC、和模板做动态时间规整匹配,**全程在板上、零延迟、不联网**。对比那些必须连云、网速一慢就卡的方案,这就是端侧离线的价值。"

### 幕 4 · 亮点三 · 拟人交互 + 情感闭环 —— 50s(3:20–4:10)
- **画面**:实拍为主。`camera velapet` 后:**拿起→睁眼 + 绿灯**,**摇一摇→开心 + 红绿双灯**(低电还会红灯闪)。板子**别正对人脸**,避免跟踪态眼睛抖。
- **命令**:
  ```
  nsh> camera velapet        # 整合演示:眼神 + 手势 + LED(演完按 Enter 退出)
  ```
  > 已确认 velapet 真驱动眼睛(EYE_EXPR_WAKE/HAPPY)与 LED(P40 红/P41 绿);拿起/摇动由加速度计驱动,不依赖摄像头。备选(更保险):`lcdtest oeye` + `lcdtest accel g` 分开拍。
- **口播**:
  > "光会算还不够,得有'陪伴感'。双圆屏是它的眼睛,板载加速度计让它有体感——**把它拿起来,它就醒过来;摇一摇,它会开心、亮起灯**。它还能读自己的电量,快没电了就像'饿了'一样提醒你。视觉、体感、声光一起,把情绪外化出来。"

## 三、剪辑与注意事项
- **总时长**:上面合计 4:30,留 30 秒缓冲,务必 ≤5:00。
- **加速**:`camera hr` 的采样等待、KWS/mic 命令的麦克风 init 刷屏日志,剪辑时 2–4 倍速或跳剪。
- **字幕**:关键数值打字幕强调(`HR = 60 bpm good`、`MATCH yundong 3.84`、`REJECTED`)。
- **离线佐证**:开头或幕 3 给"wifi 关闭/热点关闭"一个 1–2 秒特写,强化"断网可用"。
- **声音**:命令词那段现场收音要清楚;其余口播可后期配音,避免风扇/键盘杂音。
- **兜底**:低电红灯、LED 若没拍到,用口播一句带过即可,别为它反复重录。
- **片尾**:可留一帧 repo 地址 / 队伍名,方便评委记录。
