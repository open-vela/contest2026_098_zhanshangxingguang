# M3 点屏 · 背光/LCD 电源脚定位剧本（回家照做）

## 背景与结论（已确认的事实）
- 自研 NuttX 的 `lcdtest` 命令能跑、三段日志正常；但**背光全程不亮、屏无显示**。
- 原厂固件在**同一块板、同一屏接线**下能正常点亮 → **硬件没问题**。
- 用 NSH `mw` 直接读写 P25 的 AON GPIO CFG 寄存器（`0x44000464`）实测：开输入使能后
  写 `0x6`→回读 bit0=1、写 `0x4`→回读 bit0=0，**引脚电平完全随命令翻转**
  → 固件 / GPIO 驱动 / 基址 / 极性 **100% 正确**。
- 直接拉高 **P7、P13、P25** 三个候选脚都**不亮**（写入都生效，回读 0x3）。
- 机制查清：原厂"开 LCD 电源"= AP 经 mailbox 让 CP 调 `bk_gpio_ctrl_external_ldo`，
  底层就是**把某个 GPIO 配成输出高**（无 PMU 黑魔法，映射表为空）。
  **我们的 NuttX 从未做这步。**
- 原厂 flash dump 里**确认有 `gc9d01` 字符串** → 屏型号假设正确。

## 卡点
本板 LCD **电源使能脚 / 背光脚 / 复位脚的真实 GPIO 未知**：
- ARMINO 例程里 GPIO_7/GPIO_13 属其它面板/其它板，实测不适用；
- 原理图 PDF 用 `pdftotext` 抽取太乱，净表不可信；
- 本板原固件为定制，源码手上没有；
- 脚号是原厂固件代码里的立即数，`strings` 挖不出来。

## 本剧本目标
用**原厂固件运行时**的 GPIO 寄存器真值，反推出 LCD 电源/背光/复位脚，
再把"先拉电源使能脚、再点背光"补进我们的 NuttX 驱动。

## 方法 A.0（最省事，先做这个）：抓原厂启动日志
重烧原厂固件后，**从上电第一秒就开始录串口**。ARMINO 启动日志很啰嗦，LCD 初始化那段
很可能直接把复位脚 / 背光脚 / 电源脚号打出来（找含 `lcd`/`backlight`/`ldo`/`reset`/
`gpio` + 数字的行）。若日志里直接给了脚号，就不用再读寄存器了。

## 方法 A（首选，不需要 SWD）：原厂固件 CLI 读寄存器

原厂 ARMINO 固件带 CLI，且**有寄存器读命令**（dump 里确认到用法串
`<addr> <count> <0:write,1:read>`，读寄存器时最后一个参数填 `1`）。

### 步骤
1. **重烧原厂固件**（用你之前烧原厂那套方法/工具；或用 dump
   `x1_dump_20260727_221646_0xfac_0x800000.bin`）。
   ⚠️ 全片 8MB 镜像回写要用和当初烧原厂**一样的工具/偏移**，别自己猜 offset。
2. 上电，确认**屏点亮**（背光亮）。
3. 打开串口 CLI（原厂波特率可能与 NuttX 不同，先试 115200，不行看原厂文档）。
4. 敲 `help` 找那个寄存器读命令的确切名字（用法串是 `<addr> <count> <0:write,1:read>`，
   命令名很可能是 `reg`）。
5. **读整块 AON GPIO 配置寄存器**（GPIO 0~55，每脚 4 字节）：
   ```
   reg 0x44000400 56 1
   ```
   （若 count 是字节数而非字数，则用 `reg 0x44000400 0xE0 1`；读不全就加大 count。）
6. 把**完整回显抄下来/截图**。屏还亮着时读，才是"点亮态"的真值。

### 每个脚的 CFG 寄存器怎么判读
地址 = `0x44000400 + 脚号×4`。每个 32 位值的低位含义（来自 ARMINO gpio_struct）：

| bit | 含义 | 说明 |
|-----|------|------|
| 0 (0x01) | gpio_input | 引脚回读电平（RO） |
| 1 (0x02) | gpio_output | **输出值**（1=高） |
| 2 (0x04) | gpio_input_en | 输入使能（高有效） |
| 3 (0x08) | gpio_output_en | **输出使能（低有效！0=使能输出）** |
| 4 (0x10) | pull_mode | 1=上拉 |
| 5 (0x20) | pull_mode_en | 上/下拉使能 |
| 6 (0x40) | gpio_2_func_en | 1=走外设第二功能；0=普通 GPIO |

**"被原厂驱动为输出高的 GPIO 脚"判据**：`bit6=0`（GPIO 模式）且 `bit3=0`（输出使能）
且 `bit1=1`（输出高）。即该 32 位值满足 `(v & 0x4A) == 0x02`（掩 bit1/3/6）。

### 怎么用读到的结果
- 列出所有"输出高的 GPIO 脚"。
- 排掉我们已在用的：SPI `P2/P3/P4/P5`、背光 `P25`、复位 `P29`。
- **剩下那个/那几个被原厂拉高、我们没拉的脚 = 缺失的 LCD 电源使能脚**（重点嫌疑）。
- 同时核对原厂**背光脚**：原厂把哪个脚拉高当背光？如果是 P25，说明我们背光脚对、
  只差电源使能；如果是别的脚，说明我们背光脚也认错了，一并改。
- **复位脚**同理核对（我们现在用 P29，原厂用哪个？）。

### 地址速查（常用脚）
| 脚 | 地址 | 脚 | 地址 |
|----|------|----|------|
| P2 | 0x44000408 | P13 | 0x44000434 |
| P3 | 0x4400040C | P25 | 0x44000464 |

## 方法 B（备选）：SWD 读寄存器
若原厂 CLI 不方便，用 SWD（OpenOCD / J-Link）连上，在原厂固件点亮态下：
```
# OpenOCD 示例
mdw 0x44000400 56       # 读 56 个字（GPIO 0~55 的 CFG）
```
判读同上。

## 定位到脚之后（回写 NuttX 驱动，走 Claude 出日志）
把读到的真值告诉 Claude，让它在 `bk7258_gc9d01.c` 里：
1. 新增 LCD 电源使能脚常量（= 原厂拉高的那个脚），`lcdtest` **Stage A 最前面先把它拉高**，
   延时几十 ms 等电源稳定，再点背光。
2. 若背光脚 / 复位脚与原厂实测不符，一并改成实测值。
3. 顺序：**电源使能脚拉高 → 背光脚拉高 → RST 复位 → GC9D01 init → 填色**。

改完在 Kiro 里：
